# ScienceX 科研孪生实验台

ScienceX 的品牌定位是：**开源、本地优先的科研孪生实验台**。

它围绕一个细分研究对象，把数据版本、实验条件、计算模型、运行证据和研究决策组织成可执行、可重放、可比较的数字实验，让结果能够回到研究状态，并为下一轮提供可验证的候选方向。

> **核心主张：** 在数字空间复现研究，在证据回流中推进下一轮。

## 什么是科研孪生

ScienceX 所说的“科研孪生”不是实验截图、三维可视化或普通工作流，而是研究对象与数字研究状态之间可检查的对应关系。

一个最小可用科研孪生包括五层：

1. **对象层**：研究对象、科学问题、观测变量与数据结构。
2. **实验层**：变量、对照、实验条件、协议版本与验收标准。
3. **执行层**：模型、算法、工具、参数、运行环境与授权状态。
4. **证据层**：输入、输出、日志、来源、哈希、失败与不确定性。
5. **决策层**：研究者确认的结论边界、未解决问题与下一轮假设。

因此，只有结果但没有条件和版本，不构成科研孪生；只有流程但没有可重放证据，也不构成科研孪生。

## 产品层次

| 层次 | 含义 |
| --- | --- |
| ScienceX | 承载研究项目和孪生单元的科研孪生实验台 |
| 科研孪生 | 一个细分研究对象持续更新的数字研究状态 |
| 实验孪生 | 一次锁定版本、可执行、可比较、可重放的实验或计算运行 |

## 当前已经验证的能力

当前内置细胞活力教学案例构成一个**数字实验孪生单元**：

```text
版本化实验设计
    ↓
锁定模拟数据版本
    ↓
确定性 4PL 分析
    ↓
技术证据与 Artifact
    ↓
固定原版本 Replay
```

该案例能够保留正常响应、数据版本更新、缺孔失败和弱响应证据不足等不同运行状态。模拟数据只用于产品教学，不代表真实药效、湿实验验证或科学结论。

## 证据如何产生下一步

ScienceX 的“启发”不是凭空生成结论，而是从以下差异中形成可验证的候选下一步：

- 当前结论缺少哪些对照、重复或关键条件；
- 哪些变量变化最可能影响结果；
- 数据、设计、参数和输出在不同 Run 之间怎样变化；
- 外部文献与本地结果在哪些对象、条件或测量方法上存在差异。

候选输出应包含证据依据、当前缺口、建议验证和适用边界。当前阶段，这类候选建议需要调用研究者已经配置并授权的模型或工具，并且必须由研究者审核；它不是自主科学发现，也不会自动启动真实实验。

## 数字闭环与现实反馈

ScienceX 当前验证的是研究者驱动的数字实验闭环：锁定版本、运行分析、保存技术证据、生成产物并重放比较。

真实实验设备、ELN、LIMS 或观测数据要回流科研孪生，必须另外具备专用连接器、身份与权限控制、协议适配、数据质量检查和设备校准。MCP 提供扩展接口，但不能单独证明真实设备已经接入。

当前产品不宣称：

- 通用实验设备控制；
- 无人值守湿实验；
- 自动训练或更新模型权重；
- 自动确认科学结论；
- 跨所有学科通用的现实数字孪生。

## 人与 ScienceX 的分工

ScienceX 负责组织研究状态、执行获得授权的任务、比较运行结果、保存技术证据，并生成候选解释和下一步。

研究者负责定义重要问题、审核实验设计、判断证据是否可信、授权高风险或真实世界操作，并接受、修改或否决候选假设。最终科学结论始终由研究者负责。

## 演进阶段

| 阶段 | 定位 |
| --- | --- |
| 当前 | 数字实验孪生：版本、运行、证据、产物与重放 |
| 下一阶段 | 领域科研孪生：稳定的领域数据结构、专用模型和评价规则 |
| 连接阶段 | 现实反馈孪生：经验证的 ELN、LIMS、设备或观测数据连接 |
| 长期愿景 | 科研孪生网络：并行比较多条候选路线，由研究者治理与决策 |

Research Assistant、Research Agent 和 AI Scientist 描述的是 AI 角色成熟度；科研孪生描述的是 ScienceX 管理的产品对象。两者不应混为同一概念。

## 开始体验

第一次使用建议先运行[内置 3 分钟教学案例](../science/01-deployment-and-workflow.md#先用-3-分钟体验内置案例)，检查数据版本、Run、技术证据、Artifacts 和 Replay，再尝试用自己的研究对象定义输入、变量、输出指标与验收标准。
