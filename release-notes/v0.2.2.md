# ScienceX v0.2.2 — Sidecar 启动修复 / Sidecar Startup Fix

---

## v0.2.2 的重点 / What's in v0.2.2

**中文：**

v0.2.2 修复了编译后的 sidecar 在 CI 环境中启动崩溃的问题：

- **修复 WhatsApp SDK 懒加载**：`adapters/whatsapp/session.ts` 顶层静态 `import { ... } from '@whiskeysockets/baileys'` 被 server 启动路径（`src/server/api/adapters.ts` → `whatsapp/protocol.ts` → `whatsapp/session.ts`）拉入。CI 的 release build 只在根目录 `bun install`，adapters/ 的可选 SDK 未安装，导致编译后的 sidecar 启动时报 `Cannot find module '@whiskeysockets/baileys'` 并退出。
  - 类型改为 `import type`（编译时擦除，运行时不 resolve）
  - 运行时值 `makeWASocket` / `useMultiFileAuthState` 等改为 `createWhatsAppSocket` 函数内 `await import()`
  - `LOGGED_OUT_STATUS` 硬编码为 `401`（baileys `DisconnectReason.loggedOut` 值）

只有真正发起 WhatsApp 登录时才动态加载 baileys，server 模式启动不再依赖该 SDK。

---

**English:**

v0.2.2 fixes a crash where the compiled sidecar failed to start in CI:

- **Lazy-load WhatsApp SDK**: `adapters/whatsapp/session.ts` had a top-level `import { ... } from '@whiskeysockets/baileys'` that was pulled in via the server startup path (`src/server/api/adapters.ts` → `whatsapp/protocol.ts` → `whatsapp/session.ts`). CI release builds only run `bun install` at the repo root, so the adapters/ optional SDK was missing, causing `Cannot find module '@whiskeysockets/baileys'` at sidecar startup.
  - Type import switched to `import type` (erased at compile time, no runtime resolve)
  - Runtime values (`makeWASocket` / `useMultiFileAuthState` etc.) moved to `await import()` inside `createWhatsAppSocket`
  - `LOGGED_OUT_STATUS` hardcoded to `401` (baileys `DisconnectReason.loggedOut` value)

baileys is now only loaded when a WhatsApp login is actually initiated; server-mode startup no longer depends on it.

## 首次安装说明 / First-Time Installation

### macOS

安装包未签名，系统会拦截。提示「已损坏」或「无法验证开发者」时，终端执行：

*The installer is unsigned; macOS will block it. When you see "damaged" or "cannot verify developer," run in terminal:*

```bash
xattr -cr /Applications/ScienceX.app
```

### Windows

未签名安装包会出现 SmartScreen 提示，点击「更多信息」→「仍要运行」即可。

*Unsigned installers trigger SmartScreen. Click "More info" → "Run anyway."*

### Linux

```bash
sudo dpkg -i sciencex_*.deb
# 或运行 AppImage
chmod +x ScienceX-*.AppImage
./ScienceX-*.AppImage
```
