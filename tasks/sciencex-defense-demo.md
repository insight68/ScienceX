# ScienceX 答辩演示手册

项目定位：面向细胞活力实验的本地可追溯科研工作台。

## 准备与启动

使用包含本次修改的源码或重新构建的桌面端。已有安装包不会自动获得源码改动。

```bash
cd desktop
bun run build:sidecars
bun run electron:dev
```

进入「研究项目」，点击「体验完整实验案例」，选择父目录并保留「同时准备答辩对照」。系统创建独立子目录；同一位置重复创建会获得新副本。创建后只有数据与实验，没有预置运行或结果。

案例目录中的 README.zh-CN.md 和 README.en.md 是随数据生成的双语说明。所有数据均为明确标记的模拟数据，SX-101 是虚构化合物。

## 开场陈述

“一个实验结果需要回答：用了哪一份数据、按什么方案处理、结果能支持什么判断，以及重新运行是否一致。ScienceX 将研究问题、实验设计、数据快照、确定性计算、证据评价与重放连接起来。今天用一个模拟细胞活力实验展示这条链路。”

## 一次完成演示

先查看正常案例的实验蓝图与原始数据，再点击「运行完整演示」。这会实际执行四个场景和两次重放，通常产生 6 条 Run、15 个产物。实际状态以当前项目记录为准。重复点击会追加新的记录。

| 顺序 | 操作与观察 | 可以讲的项目价值 |
| --- | --- | --- |
| 1 | 查看 HepG2 / SX-101、48 小时、5 个剂量、3 个技术复孔与对照；96 孔板中分配 24 孔 | 把研究意图变成可检查、带版本的实验设计 |
| 2 | 点击正常场景，查看约 1 µM 的相对 IC50、曲线、技术证据、报告、逐孔 CSV 和结果 JSON | 原始读数经过明确计算过程形成结果 |
| 3 | 展开演示步骤并点击数据更新场景；数据集已有 V2，但 Run 使用锁定的 V1；查看子 Run 的重放一致性 | 新数据不会悄悄改变旧实验的输入；复核有具体依据 |
| 4 | 点击缺孔场景，查看缺少 A4 的失败记录；没有成功产物，失败 Run 不能重放 | 对缺失输入明确拒绝，并保留原因 |
| 5 | 点击证据不足场景，查看 completed 与 inconclusive 同时出现 | 程序运行完成与结果支持程度分别判断 |
| 6 | 保存演示记录，查看实际耗时、模拟参数误差、Run ID、数据版本、产物路径与哈希 | 结论能够返回到输入与执行依据 |
| 7 | 按需要打开 AI 证据审阅，检查预填提示词，然后主动发送 | AI 根据真实记录解释证据并提出下一步设计问题 |

点击场景后引导会收起，给结果页留出空间；通过「展开演示步骤」切换场景。数据、运行和产物页签按所选数据集过滤，顶部项目统计是项目总数。

数据更新场景采用独立数据集：V1 的模拟 IC50 为 1 µM，V2 为 3 µM，实验保持锁定 V1。演示时不要重新关联这个实验；重新关联代表主动改变输入。

## AI 段如何验收

打开 AI 审阅仅创建项目会话并填入提示词，不自动发送，也不把准备完成计作模型成功。

实际发送前配置可用模型。模型可能接收你选择的项目上下文；演示项目只有模拟数据。真实调用需相应账号和额度。

核对真实回复是否：

- 引用了存在的 Run ID、版本与产物路径。
- 正确区分正常结果、旧版本重放、缺孔失败、证据不足。
- 没有将模拟数据解释成真实药效或独立生物学验证。
- 将后续实验建议和待研究者确认的假设分开。

保留真实会话作为 AI 演示依据。确定性分析指标不代表 AI 审阅质量。

## 量化结果的口径

演示记录自动从真实 Run 提取运行状态、执行耗时、参数恢复误差、产物数和来源链。它检验本实现对已知模拟关系的恢复和异常输入的处理。

程序执行耗时不能等同于研究者完成整个任务的耗时。需要宣称人工效率提升时，使用保存记录中的对照表，在相同输入、方法和输出要求下记录手工流程与 ScienceX 的操作数、总耗时、错误和遗漏；保持熟练度可比并交替顺序。没有实测前不填提效百分比。

## 评委常见追问

“为什么用模拟数据？”——为了固定输入与预期，现场能检查正确性、故障处理和复核链路。真实药效验证属于另一个证据层次。

“创新点在哪里？”——本项目展示实验和数据版本的关联、结果到输入的追溯、执行与证据状态的区分，以及统一工作台中的复核流程。计算方法采用确定性 4PL。

“R² 很高是否证明结果有效？”——它描述拟合程度；技术复孔也不等同于独立生物学重复。这里没有置信区间、显著性结论或外部实验验证。

“重放证明什么？”——受检条件下，输入版本、参数和结果摘要的一致性。它不代表任意历史环境的完整恢复或强审计认证。

“AI 做了什么？”——真实 AI 段通过读取记录解释证据和提出设计建议。数值由确定性分析器计算，最终科学判断仍需研究者确认。

## 失败恢复

创建失败会保留部分文件并写入 provisioning-failed.json；项目登记会尝试精确撤销。错误会指出保留路径以及登记清理是否成功。再次创建使用新目录，不覆盖原文件。分析失败则保留真实 Run、错误和事件，可以检查输入后在新案例中重试。

答辩前在实际使用的电脑和安装版本完整演练一次，并保留保存记录和截图。源码浏览器验收不等于安装包验收，模拟案例不等于真实湿实验。
